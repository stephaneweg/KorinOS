Développement

Les apps de Korin s'écrivent en C, C++, C#, Rust, BASIC ou assembleur. La plupart des chaînes de compilation tournent dans Korin lui-même : on écrit, construit et lance un programme sans quitter le système.

Langages et outils

Les outils sont installés dans /devtools par leurs paquets. « Dans Korin » : le compilateur tourne sur Korin ; « croisé » : il tourne sur un autre ordinateur et produit des programmes pour Korin.

Aussi dans le système : bash, git, rg (ripgrep), pibuild pour construire un programme depuis un dossier de sources, et les agents de code Claude et Vibe, qui lisent et modifient les fichiers d'un dossier de travail et demandent avant de lancer une commande.

Les kits

Les kits sont les bibliothèques partagées de Korin (.so). Une app les appelle directement ; chaque kit garde une table d'entrées stable pour que les anciennes apps marchent encore. Le guide de l'API C est livré avec le système, dans l'app Aide.

UIKit

Fenêtres, événements, widgets, texte TrueType, jetons du thème (Givre, Onyx Noir), dialogues de fichiers, « Ouvrir avec », demandes d'élévation.

AppKit

Environnement des process, fichiers, lancement de programmes, fork et exec.

NetKit

Sockets, DNS, Wi-Fi et la connexion OAuth du système.

AudioKit

Flux PCM, capture, formats, par le mixeur du système.

MediaKit

WebM, Matroska et MP4 en VP8, VP9 et AV1 (sur FFmpeg).

GlKit et VkKit

OpenGL ES 3.0 par Mesa ; Vulkan par le pilote anv de Mesa sur le graphisme Intel (PC).

DocumentKit, ArchiveKit

Formats bureautiques, XML et CSV ; deflate, ZIP, tar et gzip.

PrinterKit, BusKit

Impression en PDF ou vers une imprimante IPP ; le bus d'événements du système (thème, volumes, réseau, son).

EmuKit, GpioKit, GpuKit

La base des émulateurs ; le connecteur à 40 broches du Pi, I2C et SPI ; le GPU V3D du Pi.

La couche POSIX

newlib et la libposix de Korin. Elle sert à porter des apps et des bibliothèques, pas à être conforme : on ajoute ce qu'un port demande.

  • Threads, signaux, fork avec copie à l'écriture, exec, tubes
  • Sockets (IPv4), select, poll
  • Un vrai dlopen pour les modules partagés
  • Portés par-dessus : bash, git, CPython, WebKit, Mesa, SDL 3, Skia, Open CASCADE, Godot, .NET, OpenSSL…

Les différences à connaître

Korin n'est pas Linux. Pas de liens symboliques, pas de /proc, pas de /usr/bin/env (les scripts commencent par #!/bin/bash). Le réseau est en IPv4 seulement, l'heure en UTC, un process ouvre 64 fichiers. Les commandes de /bin sont celles de Korin, avec moins d'options GNU ; bash, git et rg sont complets.

Les fichiers forment un seul arbre à la Unix : / est le volume système, les autres volumes sont montés dans /media, /net ou /tmp, et HOME:/ est le dossier personnel de l'utilisateur en cours.

Un premier programme

Dans l'app Terminal, avec le paquet gcc installé :

$ cat hello.c
#include <stdio.h>
int main(void) { printf("Bonjour depuis Korin\n"); return 0; }
$ gcc hello.c -o hello
$ ./hello
Bonjour depuis Korin

Pour une app à fenêtres, on inclut l'en-tête d'UIKit et on lie avec le kit ; le guide de l'Aide, rubrique « API », passe en revue fenêtres, événements et dessin. On peut aussi construire sous Windows ou Linux avec les chaînes croisées décrites dans docs/CONSTRUIRE.md.

Paquets et publication

Paquets

Un paquet est une archive avec ses fichiers et une description .ini. tools/pkg/mkrepo.py fait le dépôt : index.txt, sa signature ECDSA P-256 index.sig, les icônes et les archives. Les grosses archives vont dans une Release de GitHub.

Détails : docs/PAQUETS.md.

Documentation

Les études et références sont dans docs/ : KITS.md, ABI.md, POSIX.md, GCC.md, DOTNET.md, RUST.md, GODOT.md, PYTHON.md.

Pour les agents d'IA, AGENTS.md et les compétences de .agents/skills/ décrivent chaque kit et chaque langage.
