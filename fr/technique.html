Vue technique

Comment le système est assemblé, et ce qui a été vérifié où. Les études derrière cette page sont dans docs/.

matériel vérifié sur une vraie machine · QEMU vérifié sous émulation seulement · prévu pas encore fait

Architecture

Korin est un système à micro-noyau. Le noyau garde la mémoire, les process, les threads, l'ordonnancement, les interruptions et les messages ; tout le reste est un process.

Noyau

PC : C et FASM

Un cœur en C portable et le code x86-64. Chargeur UEFI écrit en FASM. Ordonnanceur préemptif à 1000 Hz, SMP sur tous les cœurs annoncés par l'ACPI (jusqu'à 256 ; essayé avec 1, 4 et 16 cœurs).

Noyau

Pi : assembleur AArch64

Le noyau du Raspberry Pi est encore en assembleur FASMARM, sur quatre cœurs. Son passage au cœur commun en C est prévu.

Process

Programmes ELF isolés

Un espace d'adressage par process, threads, futex, fork avec copie à l'écriture, signaux, bibliothèques partagées et dlopen, identifiants d'utilisateur.

IPC

Messages et canaux

Messages aux services, poignées, canaux et mémoire partagée ; un service peut transmettre un appel à un autre.

Services

Le reste en espace utilisateur

vfs, netd, busd, hidmanager, hwmanager, sound, authd, pkgd, keyvault, oauthd, acpid, un process par pilote.

Code commun

Une seule base de code

Kits, services, commandes de /bin et Elegant sont en C ou C++, communs aux deux machines. Ce qui ne sert qu'au Pi (GPU, DMA) reste en assembleur.

Pilotes du Raspberry Pi 4

Le Pi a été la première cible. Essayé sur un Pi 4 et sur le Waveshare PocketTerm35 (écran tactile et clavier).

  • USB : DWC2 et le xHCI VL805 (ports USB-A)
  • Ethernet (GENET), Wi-Fi CYW43455 en WPA2
  • Carte SD avec DMA et cache de secteurs
  • Son : prise jack (PWM), HDMI, USB ; micro I2S
  • GPU V3D par Mesa (OpenGL ES 3.0), utilisé par le WebGL de Jet, Avalonia et les émulateurs
  • Écran tactile GT911, connecteur GPIO à 40 broches, I2C et SPI
  • Pi 5 : préparé sans matériel, pas essayé

Fichiers, réseau et graphisme

Systèmes de fichiers

FAT32 (le volume système) et exFAT en lecture et écriture ; un système de fichiers en mémoire pour /tmp ; client et serveur SMB ; Google Drive. ext4 se lit, s'écrit et se formate, sans journal pour l'instant.

Un seul arbre

/ est le volume système ; les clés USB apparaissent dans /media/usb0…, les partages dans /net, la partition de démarrage dans /boot à la demande. Chaque compte a /home/<nom>. Pas de lettres de lecteur.

Réseau

La pile TCP/IP de Korin (IPv4, DHCP, DNS, TCP et UDP) dans netd ; TLS par OpenSSL. Serveurs telnet, FTP, VNC, HTTP (webd) et SMB.

Elegant

Le serveur de fenêtres compose toutes les fenêtres ; les apps dessinent par UIKit, et les apps OpenGL dessinent sur le GPU dans leur fenêtre.

Son

Un service de mixage avec un volume par app et le choix de la sortie ; MP3, Opus, Vorbis, FLAC et MIDI.

Sécurité

Fait pour résister aux bogues, pas encore aux attaques. Identifiants d'utilisateur, hachage des mots de passe et élévation sont en place ; les règles d'accès sont notées mais pas appliquées. Le durcissement pour le web (règles appliquées, SMEP/SMAP, ASLR) est prévu.

Construire Korin

Depuis un PC Windows avec PowerShell, Python, Git, QEMU et WSL pour les parties en C et C++.

.\build.ps1              # assemble le système du Pi et fait l'image SD
.\build.ps1 run          # puis le lance dans QEMU (raspi4b)
wsl sh tools/pc/build.sh # le noyau, le chargeur et l'initrd du PC
python -I tools/pc/qemu_pc.py run   # le système PC dans QEMU (q35 + UEFI)

Les chaînes de compilation, les ports (WebKit, Mesa, GCC, .NET, Python, Godot) et leur ordre sont dans docs/CONSTRUIRE.md. Un agent du cloud ou une machine Linux s'installent tout seuls avec tools/cloud/setup.sh.
