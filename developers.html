Developers

Korin apps can be written in C, C++, C#, Rust, BASIC or assembly. Most toolchains run inside Korin itself, so you can write, build and run a program without leaving the system.

Languages and toolchains

Tools installed under /devtools by their packages. “In Korin” means the compiler itself runs on Korin; “cross” means it runs on another computer and produces Korin programs.

Also in the system: bash, git, rg (ripgrep), pibuild to build a program from a source folder, and the Claude and Vibe coding agents, which read and change files in a working folder and ask before running commands.

The kits

Kits are the shared libraries of Korin (.so). An app calls them directly; each kit keeps a stable table of entry points so that old apps keep working. The C API guide ships with the system, in the Help app.

UIKit

Windows, events, widgets, TrueType text, the theme tokens (Givre, Onyx Noir), file dialogs, “Open with”, elevation requests.

AppKit

Process runtime, files, launching programs, fork and exec.

NetKit

Sockets, DNS, Wi-Fi and the system's OAuth sign-in.

AudioKit

PCM streams, capture, formats, routed through the system mixer.

MediaKit

WebM, Matroska and MP4 with VP8, VP9 and AV1 (built on FFmpeg).

GlKit and VkKit

OpenGL ES 3.0 through Mesa; Vulkan through Mesa's anv driver on Intel graphics (PC).

DocumentKit, ArchiveKit

Office formats, XML and CSV; deflate, ZIP, tar and gzip.

PrinterKit, BusKit

Printing to PDF or IPP printers; the system event bus (theme, volumes, network, sound).

EmuKit, GpioKit, GpuKit

The base of the emulators; the Pi's 40-pin header, I2C and SPI; the Pi's V3D GPU.

The POSIX layer

newlib plus Korin's own libposix. It exists to port apps and libraries, not to be certified: what a port needs gets added.

  • Threads, signals, fork with copy-on-write, exec, pipes
  • Sockets (IPv4), select, poll
  • Real dlopen for shared modules
  • Ported on top: bash, git, CPython, WebKit, Mesa, SDL 3, Skia, Open CASCADE, Godot, .NET, OpenSSL…

Know the differences

Korin is not Linux. There are no symbolic links, no /proc and no /usr/bin/env (scripts start with #!/bin/bash). Networking is IPv4 only, time is UTC, a process can open 64 files. The commands in /bin are Korin's own and have fewer GNU options; bash, git and rg are complete.

The file system is a single Unix-style tree: / is the system volume, other volumes are mounted under /media, /net or /tmp, and HOME:/ is the home folder of the current user.

A first program

In the Terminal app, with the gcc package installed:

$ cat hello.c
#include <stdio.h>
int main(void) { printf("Hello from Korin\n"); return 0; }
$ gcc hello.c -o hello
$ ./hello
Hello from Korin

For a windowed app, include the UIKit header and link with the kit; the guide in Help, under “API”, walks through windows, events and drawing. Projects can also be built on Windows or Linux with the cross toolchains described in docs/CONSTRUIRE.md.

Packaging and publishing

Packages

A package is an archive with its files and an .ini description. tools/pkg/mkrepo.py builds the repository: index.txt, its ECDSA P-256 signature index.sig, icons and archives. Large archives go to a GitHub Release.

Details: docs/PAQUETS.md.

Documentation

The design notes and references are in docs/, in French: KITS.md, ABI.md, POSIX.md, GCC.md, DOTNET.md, RUST.md, GODOT.md, PYTHON.md.

For AI agents, AGENTS.md and the skills in .agents/skills/ describe each kit and language.
