Les cinq points, dans ses mots :
1. Notification des apps vers Elegant pour dire qu'il peut dessiner leur contenu (present asynchrone), pour la rapidité des apps.
2. Un message dans l'autre sens.
3. IRQ pour les pilotes, pour économiser un peu le processeur.
4. Les signaux vers les apps.
5. Partage de mémoire / chaînes : un serveur de fichiers écrit dans l'espace d'adressage du client (ou le block device dans celui du FS), un programme lit un long argument dans la mémoire de l'appelant.

Leçons de cette suite : une course sous QEMU peut demander un PC chargé : 200 séries passaient seules, le blocage arrivait à la 9e sous charge (`scratchpad/hog.py`, ou un autre QEMU qui tourne) ; une trace par stderr n'apparaît pas dans telnet, utiliser stdout ; dans un vidage `info registers`, relier le binaire avec symboles et lire les registres avant de bâtir une théorie (le blocage de `posixtest mem` venait de l'horloge de time.c, pas des objets) ; compter les totaux des séries (une ligne `posixtest: N passed` par série lancée) et chercher `code de sortie -`, jamais seulement `FAIL` : un process tué n'écrit pas FAIL (31/10 : deux séries plantées passées pour bonnes, annoncées 36/0) ; `build.ps1` sans `sd` ne refait PAS `build/kernel8_sd.img` : avant d'installer sur le Pi, lancer fasmarm avec `-d ECRAN_W=800 -d ECRAN_H=600` depuis src/kernel, sinon le Pi garde l'ancien noyau et l'essai ne vaut rien (arrivé le 31/10 : « 6/6 » annoncé pour un correctif absent du Pi) ; `reboot` par telnet peut ne pas partir, vérifier la coupure du port 21 avant de mesurer ; le VNC 77 peut être pris par une autre session, QEMU ne démarre alors pas et qemu_drive attend sans rien dire ; un essai vert une fois n'établit rien pour une course (répéter, le Pi la montre bien plus que QEMU : 3 sur 4 contre 1 sur 6).
