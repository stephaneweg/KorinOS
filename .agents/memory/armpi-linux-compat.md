Le 13/11/2026, l'utilisateur choisit la **couche de compatibilité Linux** pour avoir Claude Code dans Korin, en mode chat, avec son abonnement (pas de clé d'API) : « la moins intrusive et qui demande le moins de travail (je veux être autonome) ». Revient sur l'écart du 11/11 (« sans couche de compatibilité », docs/NODEJS.md §10, docs/etude/ETUDE-CLAUDE-NATIF.md).

Forme validée en discussion : personnalité Linux par process ; le noyau renvoie les `syscall` du code de l'app vers **liblinux.so** (même process, façon Syscall User Dispatch ; les appels venant de la plage de liblinux partent comme appels Korin) ; liblinux **préchargée comme un kit** et liée au process quand la personnalité est activée (ELF Linux à l'exec, `linux prog`, app.txt) ; traduit et exécute par libposix. Kit **TuxKit** (.abi) pour les programmes de Korin (nom choisi pour éviter « LinuxKit » de Docker). Cible : version **musl** officielle non modifiée de Claude Code (x86-64 d'abord, arm64 ensuite). Dépendances relevées : epoll, eventfd, signalfd, inotify, pidfd_spawnp, posix_spawn, futex, clone, sched_affinity, recvmmsg/sendmmsg, splice, sendfile, getifaddrs (netlink), /proc/self/exe.

**Why:** Claude Code n'existe plus qu'en binaire Linux sur une fourche interne de Bun ; l'extraction (voie A) est bloquée par les conditions ; le binaire officiel non modifié est la voie propre.

**How to apply:** d'abord l'étude docs/etude/LINUX-COMPAT.md ; ordre : busybox statique → Alpine + apk → Node/Bun → Claude Code (xdg-open → Jet). Pièges : FS/TPIDR_EL0 à l'app, adresse de liblinux. Lire les conditions d'Anthropic ; couper la mise à jour automatique. Remplace la partie Claude Code de [[armpi-agent-ia-korin]] ; Vibe reste l'agent intégré ([[armpi-vibe-facade]]). Voir [[armpi-x86-pc]].

**Précision de l'utilisateur (19/11)** : pas de « personnalité Linux » dans le noyau ; une **capture générique des
syscall** : l'hôte du process déclare ce qu'il capture (plages d'adresses de l'instruction, numéros), le noyau les
lui renvoie sans savoir quelle personnalité il imite (d'autres personnalités possibles). Voir docs/etude/WIDEVINE.md § 3.2,
[[armpi-widevine]].

**21/11, chantier « hôte Linux » lancé** (docs/etude/LINUX-HOST.md) : décisions de l'utilisateur : pas de Claude Desktop (pas publié pour Linux) ; jalons 1 à 3 d'abord (exécutable glibc, Node.js, Claude Code dans le Terminal) ; le but est la CLI officielle par l'abonnement, jamais une clé d'API (le frontal, jalon 4, pilotera cette CLI en stream-json). Claude Code 2.1.330 : ET_EXEC non PIE à 0x200000 (365 Mo), glibc, 519 imports, TLS 0x5d30. **Jalon 1 fait le 21/11** : hôte lié à 0x4000_0000 (PAS 0x40_0000_0000 : libposix/newlib du PC en modèle small, symboles < 2 Go ; copie posix-lx.ld/specs dans tools/linux/build.sh), zone basse VM_FIXED du noyau [0x10000, image) (mm.c in_fixed, mm_note_image), linux_load_file + linux_exec (elf.c, exec.c), TLS de l'exe dans .lxexe_tls (exectls.S, 64 Ko en dernier dans .tbss, finit à %fs), __libc_start_main dans elf.c. Essai : sh tools/linux/exectest/run.sh (hello, tlstest, PIE et -no-pie : tout réussi). Inventaire : python3 -I tools/linux/imports.py BINAIRE --missing (Claude : 170/521 servis). Règle pour la suite : la traduction vit dans syscall.c (structures Linux), les imports simples = enveloppes de linux_syscall. Piège : Bun définit malloc/free/strdup et sigaction/signal (enveloppes RTLD_NEXT) : ce que la compat alloue et rend devra passer par le malloc de l'exe.

**21/11 (suite) : `claude --version` et `--help` marchent sous QEMU PC** (code 0). Tous les imports servis (glibc_libc.c, glibc_sys.c, syscall2.c, dl* dans elf.c). Leçons : Bun appelle les vraies `signal`/`sigaction` par dlsym(RTLD_NEXT) et un NULL rendu = saut à 0 (LINUX_TRACE_DL=1 le montre) ; le siginfo/ucontext du noyau PC ont la disposition Linux (tremplin = traduire le numéro seulement) ; newlib numérote les signaux à la BSD (table s_l2k dans syscall2.c) ; libposix a les constantes Linux pour sockets/epoll/wait/termios, pas pour AT_*, UTIME_*, SIG_BLOCK. Essai : EXTRA=/opt/claude-code/bin/claude MEM=4G ONLY='sleep:10|@200 /bin/linuxhost run /home/lx/claude --version' sh tools/linux/exectest/run.sh (pas de tube « | head » dans ONLY : la sortie se perd). Suite : -p (réseau, TLS, connexion par abonnement), l'interface dans le Terminal.

**21/11 (fin) : l'interface de Claude Code tourne dans le Terminal de Korin** (accueil, thème, écran de connexion) ; `-p` fait l'aller-retour HTTPS (« Not logged in ») ; la connexion par l'abonnement ouvre Jet sur la page OAuth d'Anthropic (BROWSER=xdg-open posé par linuxhost run ; src/sys/linuxhost/xdg-open). Pièges : MADV_DONTNEED sur l'image = relire le fichier (linux_refill, sinon '\0' dans le JS embarqué .bun) ; Claude Code n'ouvre pas de navigateur sans DISPLAY/BROWSER ; dans ce conteneur TLS est intercepté par le proxy (NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt pour les essais ; Jet n'y charge pas claude.com) ; ne JAMAIS tracer (strace) Claude Code sur l'hôte du conteneur : il lit le jeton de la session (/home/claude/.claude/remote/.oauth_token) — supprimer toute trace. Reste : auth status muet ; xdg-open et linuxhost à empaqueter (jalon 5) ; essai de la vraie connexion sur le PC de l'utilisateur.
